# V.0.1 正式版发布说明

V.0.1 是 NW-API 门户的第一个正式版基线，面向正式环境长期维护。版本目标是把前期迭代形成的能力归纳为稳定产品能力，重点说明每个模块在正式运营中的作用。

## 1. 产品定位

NW-API 提供企业级 AI API 中转门户，用于统一管理 API 接入、用户余额、模型权限、用量统计、风控规则、公告通知和系统更新。

正式版默认以公开脱敏仓库作为更新来源，开发仓库用于内部开发和版本制作，正式环境只接收可公开发布的代码与 Release 资产。

## 2. 控制台首页

- 首页集中展示余额、今日消费、累计消费、请求次数和 API Key 状态。
- 今日用量按真实调用统计，区分输入、输出和缓存 Token，便于核对成本来源。
- 最近调用表用于快速查看模型、时间、Token 规模和消费金额。
- 接口地址固定展示正式 `/v1` 入口，便于用户复制接入。

## 3. API Key 与用户管理

- API Key 页面用于创建、启停和查看 Key 使用情况。
- 用户管理用于维护账号、角色、余额、套餐和状态。
- 余额、套餐和额度共同构成用户访问控制基础。
- 管理员可通过统一后台完成充值审核、套餐调整和账号状态维护。

## 4. 用量与计费

- 用量统计按模型和 Token 类型归类，支持按输入、输出、缓存 Token 分析成本。
- 模型价格表用于维护不同模型的计费规则。
- 消耗统计用于管理员追踪整体调用量、费用和用户使用趋势。
- 余额提醒机制帮助提前发现低余额账号。

## 5. 风控与合规

- 风控规则用于定义访问限制、异常请求处理和风险提示。
- 服务条款、隐私政策和接入文档作为门户合规说明入口。
- 公告与通知用于向用户传达服务变化、更新提醒和账户相关提示。

## 6. 版本与在线更新

- 版本号显示采用正式格式，例如 `V.0.1`，界面不额外添加 `v` 前缀。
- 左上角版本区域承担版本状态展示和更新入口功能。
- 有可用版本时显示目标版本和“立即更新”。
- 已是最新时显示当前版本和发布说明入口。
- 更新检查默认使用公共仓库 `ahnerjack/nw-api-stack-public` 的 `public-sanitized` 分支。
- Git 更新模式按 tag/branch 更新正式工作区，不依赖 Release asset。
- Release 包更新模式用于可部署资产场景，会校验资产和 checksum。
- GitHub 临时超时时，若本地已有远端引用缓存，版本菜单仍可继续展示可用状态。

## 7. 公共发布与部署链路

- 私有开发仓库负责内部开发、提交和版本制作。
- 公共仓库保存可公开发布的脱敏源码。
- GitHub Release 保存正式版本的部署包、校验文件和 manifest。
- 正式服务器从公共仓库和公共 Release 获取更新，避免依赖私有仓库状态。
- 部署脚本保留正式环境配置、数据库、用户数据、密钥和运行环境，只更新功能代码与服务文件。

## 8. 界面与导航

- 左侧导航提供概览、API Key、文档、用户管理、消耗统计、风控、个人资料和退出入口。
- 版本入口集成在品牌区，减少单独系统页面跳转。
- 版本卡片使用紧凑样式，直接展示当前状态、目标版本和发布说明。
- 移动端和窄屏下保持导航、表格、卡片的可读性。

## 9. 运行维护

- systemd 管理 `xapi-portal` 等正式服务。
- Caddy 提供正式 HTTPS 入口和反向代理。
- `/var/log/nw-api-update.log` 记录在线更新排队、启动、执行和结果。
- 更新失败会记录检查状态、目标版本、更新模式和命令执行日志，便于回溯。
- 正式更新前建议保留 `/opt/nw-api-stack` 与 `/opt/xapi-portal` 的备份。

## 10. V.0.1 汇总说明

V.0.1 汇总了前期迭代形成的主要能力：门户首页、用户与 Key 管理、用量计费、风控合规、版本更新、公库发布和正式部署。后续更新日志以正式版本线为准。
