# NW-API 界面优化路线

## 1. 结论

当前界面需要整体优化，但不放在阶段 0 里做。

原因：阶段 0 的目标是“不改变线上业务行为，建立保护层”。UI 改动会同时影响用户体验、路由、模板和登录态，容易和网关保护层混在一起，增加回归难度。

## 2. 当前界面问题

- `xapi_portal.py` 内嵌大段 CSS 和 HTML，维护困难。
- 控制台、用户管理、价格、Key、用量等页面信息密度和层级不统一。
- 用户管理页大量表单堆叠，像内部工具，不像 SaaS 产品。
- 移动端和窄屏表格体验差。
- 模型权限、价格、风控等管理入口缺少组件化和状态提示。

## 3. 优化节奏

### UI-1：视觉清理，不改业务
时机：阶段 1 后
- 统一字体、间距、颜色、卡片、按钮、表格。
- 保持现有路由和表单字段不变。
- 抽离 CSS 到独立文件或模板常量。

### UI-2：控制台信息架构
时机：阶段 2 用户/Key 重构时
- 首页合并余额、今日用量、累计用量、Key 状态、最近请求。
- Key 页面改成清晰卡片和操作菜单。
- 用量页按 M Token、费用、模型维度展示。

### UI-3：管理员后台重构
时机：阶段 5
- 用户详情页：余额、Key、模型权限、账单、日志合并成一个详情视图。
- Provider/模型/价格管理改为独立后台模块。
- 所有敏感操作统一二次确认、审计和结果提示。

## 4. 框架建议

当前不是现代前端框架，是 Python 标准库 HTTP server + 字符串 HTML/CSS。

短期：继续用现有方式，避免阶段 0 扩大范围。
中期：后端 API/Gateway 迁 FastAPI；页面可以先用 Jinja2 模板。
长期：如果后台复杂度继续上升，再考虑 Vue/React + API 分离。

不建议现在直接上 React/Vue 重写，因为当前最重要的是 `/v1` 稳定、计费准确、后台安全。
